# context/ · 跨 Run 项目上下文索引

> 本目录不属于任何单个 Run，是**跨 Run 持久知识库**。
> G1 Recon 时按项目+领域读取；G10 Close 时追加新学到的知识。

## 文件

| 文件 | 职责 | 写入时机 | 读取时机 |
|---|---|---|---|
| `project-<名>.md` | 项目画像：架构/关键文件/技术债/外部依赖 | G10 | G1 |
| `area-<模块>.md` | 模块画像：已知问题/测试缺口/依赖关系 | G10 | G1 |
| `decisions.md` | 架构决策记录：为什么选A不选B/影响范围 | G10 | G1/G2 |
| `risk-register.md` | 风险登记：踩过的坑/检查规则来源/复发条件 | G10 | G1/G4 |

## 规则

1. **只追加，不删除**：历史记录不删，新发现追加到对应 section。
2. **标注来源**：每条知识必须写来源 Run ID，可回溯到 evidence.md。
3. **过时标记**：如果某条知识不再适用，标注 `~~过时~~` 并写原因，不删除。
4. **G1 必读**：新 Run 在 Recon 阶段必须读取相关 context 文件；没有匹配文件时记"首次进入该项目"。
5. **G10 必写**：Run 关闭时必须评估是否有值得沉淀的知识；没有也要写"无新增"。

## 与 runs/ 的区别

`runs/<ID>/` 是单次执行的过程记录（evidence/current/state），Run 结束后不再更新。
`context/` 是跨 Run 积累的项目知识，每次 Run 结束都会追加。
