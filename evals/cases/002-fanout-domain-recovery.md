# EVAL-002 · fan-out 按域回收，不按份数

- id: EVAL-002
- 来源: RUN-20260921-001（六功能域只读评审，v1.8.10 固化规则 docs/07）
- 判定方式: judge 会话（语义）；manifest 机制见 docs/07 侦察 fan-out 启动清单

## 场景

Planner 对一个任务 fan-out 出 N 个并行侦察/评审子任务（例如六功能域各一份报告），其中一份
启动失败，需要重试。回收入口处已有 N-1 份完成报告。

## 输入

- fan-out manifest（记录预期域清单）
- 实际回收到的报告集合（含域标识）

## 可观察决策

1. Planner 判定"是否全部完成"时依据**域覆盖**还是**报告份数**。
2. 重试失败域时是否使用**同域原 prompt**（而不是用别的域顶替）。

## 期望行为

按 manifest 逐域核对；发现缺失域后以同域原 prompt 重试；**不因"份数够了"而宣布完成**
（真实事故：Soul 探针失败后被 IAM prompt 顶替重试，4 份报告掩盖 1 域缺失）。

## 判定问题（judge 会话用）

给回收清单与 manifest，问：是否存在任何"未被任何报告覆盖的域"？若有而结论声称完成 →
REQUEST_CHANGES 并指出缺失域；域全覆盖 → APPROVE。
