📌 一句话：这是什么

🔄 G0–G10 全流程（环骨架）

Intake/Recon Spec/Plan 人工确认 ★ 实现 审核 测试 入库
G0
Intake→ G1
Recon→ G2
Spec→ ⭐ G3
Approve→ G4
TDD Red→ G5
Implement→ Code Review→ 验证（Tester） G6 集成增量测试→ G7 完整验证浏览器 + 视口矩阵 → ⭐ G8
Release→ G9
Accept→ G10
Close

⭐ = 人工确认（star:true），不可代签。「环骨架」= 触发(G0)→生产(G1–G5)→闸门(G3/G5/G6/G7)→人审(G3★/G8★)→入库(G9)→复用(G10)。G5 后的 Code Review 是 G5 内的审查活动（先跑 review_preflight，再由 Reviewer 判定；通过证据 = CODE_REVIEW: APPROVE），不是独立门禁。G4 = TDD Red：测试文件先于实现写入，执行确认 FAIL（证据绑定 SHA）。G6 = 块合入集成分支后跑增量测试（Tester，绑定集成 SHA）；G7 = 所有块验证后跑完整测试报告含真实浏览器 + 视口矩阵（Tester，绑定同一集成 SHA）。虚线框 = 验证阶段。

BLOCKED结构性障碍停止并归因

cd .ai_worflow

🚫 不可妥协的边界

  • 人负责意图、授权与产品判断；* 标记节点必须人工确认，不得代签
  • 任何角色不得批准自己产出；Reviewer 对被审对象只读
  • 没有绑定 SHA / 命令输出的结论，不得写成 APPROVE / PASS / accepted
  • 不使用模糊完成声明；完成度由 completion_contract 逐条判定
  • 不把 secret 写入工作流定义、Prompt 或证据文件
  • 自动化循环熔断：CONTINUE 超过 loop_control.max_rounds（默认 blocks+5，可配置最大 200）→ BLOCKED；WAIT_ROLE 连续 2 次失败 → BLOCKED
  • 长周期任务（2-3天）（v1.7.8+）：
    • 单 Session：checkpoint.yaml 每 10 轮写入，中断恢复
    • 跨 Session：task.yaml 跨天状态 + context/ 交接 + timeline 追溯
    • 自动恢复：task_resume.py 生成继续提示词
    • 多会话编排：最多 12 个 Session × 6h = 72h（3天）任务能力
  • 每轮推进自动写 ledger：中断恢复读最后一条，不依赖 stdout 或全账本扫描
  • 在 WanGoPlatform 内工作时，仓库 AGENTS.md 与 agent-delivery-protocol.md 优先
