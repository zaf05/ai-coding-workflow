# 交接契约

> 吸收自：GoPS 篇「上下文连续性 > 工具特长」、a10 丶单向箔「多天 AI Coding 工作流」、a03 仁「Review = Candidate Generator」
> 权威来源：`../../../docs/04-roles.md`、`../../../docs/00-overview.md`。

每次跨角色委派必须一次给全，缺任一项接收角色应 `BLOCKED` 而不是猜测：

1. Run ID 与块 `label`；单一角色动作（做什么，不做什么）
2. 产物路径与对象修订；相关 Spec/计划版本
3. 精确 `base_commit` / `head_sha` / `tested_sha`（完整 SHA）
4. 适用 Finding / Defect ID
5. 允许写入路径与受保护路径
6. 预期输出契约（用哪个模板、写到哪）
7. 停止条件与预算（token/时间/轮次、熔断阈值）

完整材料通过持久路径与不可变身份引用，不重复粘贴，不依赖完整对话历史。
"审核一下""完成它"这类请求不充分。

## 上下文连续性 > 对话历史（吸收自 GoPS）

> GoPS 篇原则：**指定一个主线 Agent 对上下文负责到底，其他工具只做入口或补位。** 上下文的连续性比工具的特长更重要。

本工作流对应：
- 交接时，Planner 必须把接收角色需要的**最小必要上下文**写入 `current.md` 的对应块章节。
- 接收角色启动时先读 `current.md` 和 `state.yaml`，不依赖上一轮对话的聊天历史。
- 交接内容不是"你去看之前的对话"，而是精确的对象引用 + 角色边界 + 预期输出。

## 跨会话恢复的交接（吸收自 a10）

> a10「用一个完整需求跑通多天 AI Coding 工作流」：跨会话恢复不是"想起来接着做"，而是从证据中重建上下文。

跨会话恢复时的交接要求：
- `state.yaml` 的 `current_block_label` 指向下一个待执行块。
- `current.md` 中对应块章节包含：目标、已完成的前置条件、当前 `base_commit`、待解决的 Finding（如有）。
- 不得出现"继续做"这类只依赖会话记忆的指令——必须引用证据文件中的具体对象。
